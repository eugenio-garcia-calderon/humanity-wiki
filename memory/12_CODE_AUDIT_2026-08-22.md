# Code audit — 2026-08-22

Eugenio asked for it in these words: *«haz una evaluación de todo el código y di
qué cosas están duplicadas con tanto cambio, y quizás por ejemplo hay módulos de
ventana que se podrían unificar bajo el mismo código — pero antes de hacerlo
tienes que pensarlo y luego testearlo muy bien para no romper ninguna
funcionalidad».*

Everything below is **measured**, not estimated. The two items marked DONE were
unified and tested the same day; the rest are listed with a number and a
recommendation, because acting on all of them at once is how a refactor breaks
things nobody notices for a week.

Total: **70.682 lines** across `src/`.

---

## 1. Window modules — DONE

He was right, and it was the clearest case of the lot. There were **three kinds
of window** and each drew its own buttons:

| Where | Minimise | Grow | Close |
|---|---|---|---|
| Desktop windows (`GestorVentanas`) | `Minus` | `Square` / `Copy` | `X` |
| Browser (`Navegador`) | — | — | its own `X` |
| Side panel (the AI dock) | — | **did not exist** | `ChevronDown` |

Three drawings of the same gesture is how they end up meaning different things:
the desktop used a square for "maximise" while the side panel had no way to grow
at all — which is exactly what Eugenio hit.

**Now**: `src/components/ventanas/controles.tsx` holds one `ControlesVentana`
and all of them use it. Growing is the diagonal-arrows icon (`Maximize2` /
`Minimize2`), the same one he screenshotted, and it is a toggle in both
directions. Verified in the browser: desktop window, side panel expanded, side
panel restored, closed.

The new `VentanaLateral` reuses the desktop windows' own mechanism — an
`<iframe>` of the real route with `embed=1` — rather than mounting a second copy
of each page. One page, one implementation.

## 2. `POST /api/uploads` — DONE

The same upload request was written by hand in **16 places**: the page editor
(×4), the 3D visor (×7), the kanban, the profile, the canvas, the presentation,
the attachments panel, the publication creator, the image editor, the sidebar
rename popup, and the paste pipeline.

They were not 16 identical copies, which is the expensive part:

- some sent the `File`, others `await f.arrayBuffer()`;
- some defaulted the MIME type, others sent an empty one;
- error handling was different in every one — three threw, five returned, two
  said nothing at all.

**Now**: `src/utils/subir.ts` exports `subirArchivo(file)`, returning
`{ url, bytes, type, esImagen, clase }` or `{ error }` — a result, never a
throw, so a caller cannot forget to handle the failure and leave the screen
half-done. All 16 call sites migrated; `grep "api/uploads?type="` returns
exactly one hit in `src/`, and that one is the helper.

Tested end to end after the migration: dropping a file into a page uploads it,
renders it, and removing it cleans up.

## 5. Dead code — retired to `papelera/`

Eugenio: *«procura borrar todo lo que ya no sirve […] déjalo en una carpeta de
papelera que dentro de 30 días se borre de forma definitiva, con un programa ya
hecho, que no tengas tú que acordarte».*

Ten files, ~2.900 lines, all orphaned by the visor rewrite: `Aldea`,
`EditorAspecto`, `Efectos`, `Ficus`, `Hierba`, `Nubes`, `Oleadas`, `Pantalla`,
`Sendas`, `calidad`.

The mechanism: `scripts/papelera.mjs mover|vaciar` plus a **daily GitHub
Action** (`.github/workflows/vaciar-papelera.yml`) that deletes anything older
than 30 days and commits the deletion. It runs whether or not anyone's Mac is
on, and nothing is lost even then — every move is a commit.

`tsconfig.json` excludes `papelera/`: what is in there is retired on purpose and
half its imports no longer exist.

**What was deliberately NOT retired**, so nobody deletes it later thinking it is
leftover: `Objetos`, `Detalles`, `CasaReal`, `Camper`, `Vehiculos`, `Agua`,
`Modelos`, `Senales`, `Agentes`, `Robot`, `Interior`, `Vida`, `BosqueComestible`
and `EdificiosProyectos`. They are the catalogue of things a person can still
place in the world, the products (the DJI, the camper van — Eugenio asked for
those by name), or types the visor still imports.

## The rule this audit kept running into

Most of the duplication above is not a copy-paste problem. It is that **the same
decision was made in several places**: what an upload's error message says, what
"grow this window" looks like, whether a click outside closes something. When
that decision lives in one place, changing it is one edit; when it lives in
sixteen, the day it changes, some of them stay behind — and the ones that stay
behind keep working until the exact case that breaks them.

That is the same illness as the root principle in `src/server/CLAUDE.md`, seen
from the other side.
